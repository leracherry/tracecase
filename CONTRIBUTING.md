# Contributing to TraceCase

Thanks for helping make browser bugs easier to reproduce. TraceCase is an experimental alpha; focused fixes, reproducible bug reports, privacy tests, and documentation improvements are welcome.

## Before starting

Check the [roadmap](docs/ROADMAP.md) and existing issues. For a substantial feature or a format change, describe the problem and proposed scope in an issue before investing in a large implementation. Report vulnerabilities through [SECURITY.md](SECURITY.md), not a public bug report.

Use synthetic data. Never commit real user recordings, authentication state, credentials, or private screenshots.

## Development setup

Use Node.js 22.12+ and run these commands from the repository root:

```sh
npm ci
npx playwright install chromium
npm run build
npm run check
npm test
```

On Linux, use `npx playwright install --with-deps chromium` when system dependencies are needed. To match CI’s browser coverage:

```sh
npx playwright install chromium firefox webkit
TRACECASE_CROSS_BROWSER=1 npm test
```

PowerShell: set `$env:TRACECASE_CROSS_BROWSER="1"` before `npm test`.

For the viewer, `npm run dev -w @tracecase/viewer` starts the development server. After rebuilding the extension, reload it in `chrome://extensions` and reload the target tab. [Repository map →](docs/ARCHITECTURE.md)

## Make a focused change

1. Create a branch for the change and keep unrelated edits separate.
2. Preserve privacy and artifact-validation boundaries. Add meaningful tests for changed behavior.
3. Update user-facing docs when a command, workflow, or supported capability changes.
4. Run the relevant checks, then explain the problem, resulting behavior, and validation in your pull request.

The test suite uses production extension builds in isolated profiles, synthetic framework apps, and real Playwright browsers. Enhanced extension tests pregrant debugger permission only in temporary test copies.

## Documentation and screenshots

Run `npm run docs:check` for local links and anchors. Use relative links within the repository and descriptive image alt text. Keep the README focused on orientation and first use; put detailed reference material in `docs/`.

Refresh workflow screenshots with:

```sh
npm run build
npm run docs:screenshots
```

Inspect each image before committing. The script records the synthetic checkout demo, uses a temporary browser profile, and never opens a real account. See [screenshot provenance](docs/WORKFLOWS.md#refresh-these-screenshots). Documentation-only edits do not need a full browser suite unless commands, capture tooling, or product behavior changed.

Use Prettier on the files you edited. `npm run format` formats the whole repository; review the diff to avoid unrelated changes.

## Generated files and compatibility

- Schema changes must preserve supported artifact versions. Run `npm run schema` and update the [format specification](docs/spec/0.2.md).
- The standalone network helper in `packages/playwright-export/src/runtime.generated.ts` is generated by `npm run build:export`; edit its source modules instead.
- Brand assets are synchronized by `npm run brand`; follow the [brand guide](docs/BRAND.md).
- Keep workspace versions aligned during releases. Follow the [release guide](docs/RELEASING.md); do not include publishing credentials in changes.

## Pull request checklist

- The change solves a stated problem and stays within its scope.
- Relevant checks pass, and any unverified behavior is explained.
- Tests and fixtures contain synthetic data only.
- Documentation and screenshots reflect changed behavior.
- Format, privacy, and compatibility impacts are described.
